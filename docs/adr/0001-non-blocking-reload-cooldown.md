# 輪詢刷新改用非阻塞冷卻，不在 handler 內 sleep

主迴圈約每 50 毫秒重入一次平台 handler，但 handler 過去在等待刷新間隔時直接 `asyncio.sleep()` 睡滿整個間隔，凍結主迴圈，使購票流程的偵測與連鎖執行被刷新間隔節流（upstream #376，本 repo issue #3）。我們決定：輪詢刷新的等待改為記錄在既有 `_state` 中的冷卻到期時間戳，handler 記錄後立即返回，由主迴圈的自然重入負責在每次進入時先重查頁面狀態、到期才執行刷新。冷卻判斷抽為 `src/util.py` 的純函式，讓這條規則可以獨立測試。

## Considered Options

- **另開 asyncio 背景 task 專責刷新計時**：刷新與購票流程真正並行，但兩者共用同一個瀏覽器 tab，刷新可能在流程執行到一半時重載頁面，並發風險與除錯成本都高，否決。
- **維持 sleep，但縮短或分段 sleep 後重查**：改動最小，但主迴圈仍被 handler 佔住，其他平台的派發與暫停、停止檢查都被延遲，且實際週期仍是執行時間加間隔，否決。

## Consequences

- 冷卻以 wall-clock 計時，暫停期間照常流逝；恢復後若冷卻已到期，會立刻刷新一次。這與既有 `sold_out_cooldown_until` 的行為一致。
- 刷新間隔的語意不變：0 表示停用輪詢刷新；冷卻只約束輪詢刷新，復原刷新不受影響。
