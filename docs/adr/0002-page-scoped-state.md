# 平台狀態改用頁面狀態 module 宣告生命週期，取代純 dict 慣例

各平台模組過去以模組層級的純 dict（`_state`）保存跨輪次狀態：鍵的字串名稱就是唯一的介面，生命週期全靠慣例 — 何時寫入、何時清除散落在各 handler 與平台主函式中。#3 的刷新冷卻截止時間因此跨頁殘留，靠 code review 才發現（冷卻鍵的清除邏輯事後補在主函式裡，離寫入鍵的 handler 很遠）。架構健檢（2026-11-19）將此列為首要改善項：tixcraft 有 29 個狀態鍵、kktix 44 個，全 repo 的主動清除點只有個位數。我們決定：在 `nodriver_common` 提供一個 dict 相容的頁面狀態 module，各平台集中宣告每個鍵屬於哪個頁面（頁面狀態）或跨頁存活（並寫明理由）；平台主函式每輪以 page_id 宣告目前頁面，page_id 改變時，該頁面之外的頁面狀態自動清除。

## Considered Options

- **維持純 dict，只加中央清除函式與文件規則**：#3 retro 已在 CLAUDE.md 立下「新鍵必須寫明清除時機」的規則，但規則靠 review 把關、介面本身仍不存在，同類缺陷只是被提醒、不是被結構擋下，否決。
- **每個平台各自長出自己的狀態管理慣例**：延續現狀的分裂（10 個模組 10 種寫法），且清除知識無法集中驗證，否決。

## Consequences

- 新鍵預設宣告為頁面狀態；跨頁存活必須在宣告處寫明理由。未宣告就被寫入的鍵視為跨頁存活（相容既有行為），宣告完整性由盤點與 code review 補齊。
- 「同頁」以 page_id 是否改變判定：同頁重新載入、主迴圈每輪重入都不清除；無法分類的頁面（page_id 為 None）視為離頁，清除全部頁面狀態。
- Pilot 先行 tixcraft 與 TicketPlus（#3 的 6 個冷卻鍵全數改為宣告式清除，移除主函式中的手寫清除）；其餘平台模組逐個推廣，不一次全改，以控制與上游同步的摩擦。
- dict 相容：既有的 `_state["k"]`、`.get()`、`.setdefault()`、`.pop()` 寫法全部照常運作，handler 內部不需重寫。
